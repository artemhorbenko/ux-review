# Report specification

The report is one self-contained HTML page. `assets/report-template.html` implements everything below and renders it from one `<script type="application/json" id="audit">` block; you write only that JSON (`audit.schema.json`, example in `assets/example-audit.en.json`). Rebuild from this spec only if the template cannot be used.

## Look

Annual-report style: white ground, black ink, one vermilion accent (#ff4a1c) only for blockers and the top 3 fixes, amber for friction; dark theme on #120d0b (the page follows `prefers-color-scheme` and a `data-theme` attribute on the root). Titles in Sofia Sans Condensed 800, text in Sofia Sans (both cover Latin and Cyrillic). Simple stroke SVG icons per lens, no emoji. It must work at 360px: tables become stacked cards, the task strip wraps under its label. Every derived number (ICE, UX index, quick wins, heuristic counts, confidence, tasks done, blocking steps) is computed by the template, never typed.

Headings state their point ("Decision support and error states score lowest"), not a topic ("Lens scores"). If any data is partial or assumed, say so once in the small label at the top. Footer: generated by ux-review.

## Sections, in order

1. **Header** - headline = the main finding (usually the failed or worst task, with the concrete cause); one-sentence lead; KPI row (up to 4): tasks done without trouble (`{done} of {tasks}`), blocking steps (`{blockers}`), UX index (`{health}/100`), and one measured number or a `null` KPI that shows "no data". Then the persona line and the **task strip**: one row per key task, one square per step coloured by friction (0 ink, 1 light amber, 2 amber, 3 vermilion, null hatched "not tested"), the task outcome badge, and the worst step named under the row.
2. **Lenses** - radar of the 10 lens scores beside a grouped list with meters (5 groups: foundations, find and understand, act and recover, decide with confidence, reach everyone).
3. **Walkthrough** - per task: id, title, outcome, goal, and a table of steps with friction, Know / See / Recover marks (Yes, Partly, No, —) and what was seen.
4. **Heuristics** - Nielsen's 10 heuristics with the number of issues breaking each, the worst severity and the issue numbers.
5. **Impact-effort matrix** - numbered dots per issue; filled = fix, outlined vermilion = rethink; quick-wins quadrant tinted.
6. **Issues table** - sorted by ICE, then severity; filter chips (all / fix / rethink / major and blockers); columns: #, issue (observed/hypothesis badge), where (task · step), lens, severity, type, ICE with bar, I, C, E; top 3 highlighted. On phones I, C, E are hidden and shown inside the ICE cell.
7. **Next 3 fixes** - cards with hypothesis, success metric, cheapest check.
8. **Full plan for every issue** - one collapsible row per issue, top 3 open, "expand all". Summary: number, title, lens, where, severity, ICE, type, effort, badge. Body: **What we saw**, **Proposed change**, heuristics, metric, effort, risk; **What to do** (2-5 steps naming real pages and controls); **Verify with users** (task, success, what to watch). Top 3 also show alternatives, risk type, threshold, pre-mortem, and copy variants for wording changes.
9. **Usability test** - participants, how many, format, before the session; five task cards (scenario as a goal, start, success, watch, ask afterwards); what to measure; what to do after.
10. **Data and confidence** - sources with statuses, confidence meter (ok = 1, demo = 0.6, no = 0, averaged), start answers; collapsible glossary; collapsible "how this report was made".

## Data shapes and language

The full shape is in `audit.schema.json`; `scripts/validate_audit.py` checks it plus the skill's rules. Easy to get wrong:

- `lang` (`uk` or `en`) picks the interface labels (`UI`) and heuristic names (`HEUR`). For another language, add entries with the same keys.
- `text` holds the report's own words: `label`, `headline`, `lead`, `tasksNote`, a heading `…H` and intro `…P` per section (`lenses`, `walk`, `heur`, `matrix`, `ops`, `next`, `plan`, `test`, `data`), `how` (list), `footer`. Tokens `{health}`, `{qw}`, `{n}`, `{conf}`, `{done}`, `{tasks}`, `{blockers}` are filled in; `[[words]]` turns red. All text is escaped. A missing or empty key removes that element.
- `persona`: one line, shown above the task strip.
- `kpis`: up to 4 `{v, l, hot?, src?}`. A literal number needs `src` = a name in `sources`. `v: null` shows "—" and "no data".
- `tasks`: `[{id, t, short?, goal?, out: ok|hard|fail|stop, steps: [{s, page?, f: 0-3|null, k, see, rec: y|p|n|null, note}]}]`. A step with friction 2+ needs a `note`. The step you did not perform (a submit) has `f: null`.
- `lenses`: 10 `{k, n?, i, g, s}`; ids and groups in `lenses.md`.
- `ops`: `{t, l, ln, x: opt|ex, ev: obs|hyp, sev: 1-4, task?, step?, h: [H1..H10], I, C, E}`; ids are 1-based positions. `detail` and `plans` are keyed by that id as a string.
- `detail[id]`: `why`, `change`, `steps`, `metric`, `effort`, `risk`, `test: {task, success, watch?}`; optional `accept`, `depends` (`UX01`…), `copy`; top 3 add `alt`, `rtype`, `thr`, `pm`.
- `testplan`: `{who, n, method, before?, tasks: [5 × {t, start?, success, watch?, ask?}], measure?, after?}`.
- `answers`: `{q, a, skipped?}`; `sources`: `{name, note, status}`; `glossary`: `{term: {g, d}}`; `rules`: list for the hands-off file.

## Tooltips for terms

Every abbreviation and method name (ICE, SEQ, IA, 404, autocomplete, aria-expanded, think-aloud, pre-mortem…) is a dotted-underlined button with a tooltip: term, a 2-4 word gloss, one or two plain sentences, ideally with this product's own example.

- Desktop (hover-capable fine pointer): opens on hover.
- Phones and tablets: opens on tap; a second tap or a tap elsewhere closes it.
- Keyboard focus opens it, Escape closes it; scrolling more than 40px closes it.
- Definitions live in one glossary object; the script wraps the first occurrence of each term per paragraph or cell. Terms match case-sensitively, so add both cases when a term starts sentences.

## Mobile tables

In stacked (phone) tables every cell is a flex row of label + value, so its content is wrapped in one `<span class="cv">` - after terms are wrapped, and again after every filter re-render. The walkthrough tables and the issues table both stack.

## Robustness

- Charts are drawn at real pixel size with a ResizeObserver; bars, meters and the task strip are HTML.
- All script sits in one block at the end of `<body>`, wrapped in `{ }`; check it with `node --check` before delivery.
- `localStorage` is not needed; do not depend on it.
